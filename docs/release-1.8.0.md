# FrpDeck 1.8.0

新增免费应用网关联动，整合监控详情，并继续完善配置与运行状态判断。保留 1.7.4、1.7.5 的 Lucky 兼容与安全修复，原主题、功能、授权及数据目录继续沿用。

## 本次更新

- **免费应用网关联动**：所有版本均可连接独立部署的 fn-knock，在 FrpDeck 中管理应用域名、访问账号、防护及会话。当前接口基线为 fn-knock 2.5.3，感谢上游开源项目。Lucky 可继续使用；连接和导入配置不会自动修改 DNS、接管监听端口或停止 Lucky。
- **统一监控**：普通总览与多机实时共用设备详情。详情保持单页：顶部标题、时段、刷新与数据保存设置，下接访问链路、集中运行指标、连续趋势、流量分析及设备明细。保留网速、延迟和探测失败率等板块。
- **扩展设备指标**：按实际环境采集 CPU 型号/核心/频率、Swap、负载、磁盘读写、网卡、温度和 PSI。明确采集来源及不可用状态；扩展硬件字段是当前快照，不承诺历史回看。
- **状态与配置修复**：完善 IPv6、Docker 网络地址、端口、首次管理员设置和写入失败处理；连接拒绝、超时、不可达不再直接认定容器停止。基础 TOML/INI TCP/UDP 导入先校验再保存，不支持的高级选项明确拒绝。
- **线路与规则保护**：修复不同入口切换、迟到读取结果、外网自定义端口和网关规则归属判断；保留独立 Lucky/网关规则。纯 FRP 端口转发不再要求 Lucky。
- **体验到期处理**：到期后固定一条保留线路，其余停用但配置保留。可提前选择；未选择则优先已启用的默认线路，再选最早添加且启用的线路；原本全关闭则保持关闭。基础版不可切换其他线路，永久授权不受影响。

## 升级

升级前导出配置，并另行备份**完整数据目录**，包括安装标识、授权和网关连接/归属文件。普通配置导出不包含全部登录及认证数据，不能代替完整备份。

- 飞牛：待应用中心对应版本可用后，通过应用中心升级，沿用数据目录与原端口。版本记录发布不代表应用中心已经上架。
- 已有 Docker：保持原挂载、环境变量和端口，通过原安装渠道更新镜像并重建原服务。不要删除数据目录或执行删除数据卷的命令。
- 旧探针仍可提供基础数据；查看新指标时更新对应探针。内核不可读取的字段显示不可用，无需为补齐指标随意增加权限。
- 回退前停止服务，恢复升级前完整备份并使用 1.7.5 原镜像及部署参数；不要假设 1.7.5 可以识别新增网关数据。

## 验证与范围

- 全量 Go 格式、vet、竞态、构建、依赖及隐私检查通过；11 组浏览器回归通过，正式提交及合并后的主分支 CI 均通过。
- 普通版与飞牛版各三个架构的镜像已完成运行验证。使用 Docker Hub 正式镜像验证了首次配置、从 1.7.5 保留数据升级、真实 FRP 隧道和 IPv6 应用检测。AMD64、ARMv7 在本地兼容运行环境测试，不能代替实体硬件验收。
- 使用官方 Lucky 2.5.1、2.7.2 以及独立 fn-knock 实际程序完成本地集成验证。反馈用户的 Lucky 2.6.2 原程序不可得，仍未验证。
- 完整硬件支持取决于主机、内核及容器可见范围；公共证书签发、DDNS 和外部身份提供商需按部署环境验证。
- 本次未改变既有飞牛包权限架构。物理 NAS 的安装、覆盖升级、卸载及应用中心审核仍需按渠道验收，不将容器测试当作实机验收。

官网与公开仓继续只展示产品说明和版本记录，不提供独立安装包或应用源码。
