# FrpDeck 1.8.1

本次重点修复 NAS 公网流量统计、探针升级兼容与异常恢复，并保护独立 Lucky 规则。飞牛应用名称统一为 **FrpDeck 内网穿透管家**。

## 修复内容

- NAS 公网流量和业务服务流量分别展示，NAS 趋势与流量构成共用日期范围，避免把两种口径相加。
- 修复无效采样、面板重启和探针周期变化后的计数基准；保留原密钥、历史及旧每日记录，缺少小时明细时不伪造曲线。
- 改善 IPv6 容器、共享网络地址、高位 UDP 和回环端口归属；同端口多 socket 无法唯一识别进程时保留端口显示。
- 公网 IPv4 接口不再整段当作局域网；IPv6 可用内网地址辅助识别或明确声明接口角色，不确定时提示范围。复杂混合网络仍需核对实际拓扑。
- 计数表恢复不依赖英文报错，失败有超时和退避；随机计数周期避免依赖系统时钟，极长空档兜底标注估算。
- 保护其他安装或独立维护的 Lucky 规则，避免远程线路同步误改现有目标端口。
- 飞牛包显示名称与桌面入口统一为“FrpDeck 内网穿透管家”，开发者和发布者仍为 6uos。

## 升级要点

**使用正式 1.8.0 NAS 公网探针时，需要同时更新主程序与 NAS 探针。**

1. 升级前备份完整主程序数据目录，包括配置、安装标识、授权及探针历史。
2. 保留原端口、数据挂载、环境变量、密钥和探针回调地址，更新主程序。
3. 通过原 Docker 部署界面拉取新版探针镜像，保留参数重建原 NAS 探针容器。单纯拉取或重启容器不会替换运行中的镜像。不必重新生成密钥，不要清空历史或删除数据卷。
4. 在探针窗口核对运行版本及采集状态。首次建立基准后开始显示差值，UDP 监听端口需稳定约一分钟。

只更新主程序仍可保留历史；旧 NAS 缺少计数周期时提示升级并暂停新版公网记账，不会把它伪装成正常零流量。旧 VPS 探针的基础采集继续兼容；需要新端口筛选能力时按需更新。

IPv6-only 家庭 LAN 或特殊混合接口可用探针的可选 LAN/WAN 接口声明明确边界；普通原参数不强制改变。没有测得或异常退出丢失的历史字节不能自动找回；统计范围调整不会重算旧历史。业务服务、NAS 公网与隧道流量可能覆盖同一批数据，不能相加。

飞牛应用中心以实际审核上架版本为准，本版本记录不代表已提交或已上架。官网和 GitHub 不提供独立安装附件。

## 验证与限制

本轮全量 Go 测试、竞态检测、最低 Go 1.23.12 和正式 1.27.2 Alpine 检查通过；15 组浏览器回归、24 个 NAS 页面布局通过。隔离 Linux 实际验证 nftables、IPv4/IPv6、DNAT、UDP、302 直连等价路径及探针重启；面板容器重建后历史与密钥保留。

这些验证不能代替真实飞牛/极空间、Lucky 与 FRP 组合验收。复杂网络的 IPv6 角色仍需确认；含实测字节的旧累计偏移不会按固定 TTL 强行淘汰，长期名称频繁变化仍有积累边界。实际硬件、系统防火墙及加速/卸载能力以部署环境为准。

回退前停止服务，恢复升级前完整数据备份并使用原 1.8.0 部署参数；不承诺旧版本具备新版防重复和统计能力。不要通过清空数据来完成回退。
