# 安全设置与自动端口保护

FrpDeck 1.7.3 包含以下安全能力：独立会话列表及单独退出、可配置失败登录封禁、手动 IP/网段/浏览器标识封禁、内网解除，以及 VPS 网页端口自动执行与回执。现网升级需要先备份实际配置目录和 VPS 防火墙。

## 登录与封禁

“账号安全”显示最近 100 次登录尝试，服务器保留最多 500 条；可见来源 IP、来源类型、浏览器上报信息和浏览器标识。已有部署的自动失败登录封禁默认保持关闭，配置默认值为连续 5 次、临时 15 分钟、累计 10 次永久封禁。

用户可以开启或关闭自动防护，设置连续次数 1–100、临时时长 1–43200 分钟、累计永久阈值 0–10000。永久阈值填 0 表示关闭；非零时需不低于连续阈值。常用时长为 5/15/30/60/1440 分钟，也可自定义。

只统计服务端实际核对失败的账号密码或第二因素；被封期间拒绝的请求不新增计数。成功登录清除连续计数，累计计数保留；管理员解除时清零。多个用户共享同一公网出口会共用 IP 计数。基础全局限流独立保留。

手动名单支持单个 IPv4/IPv6、CIDR 网段和浏览器标识；0 分钟是永久，其余是指定临时时长。关闭自动防护不撤销手动名单。解除必须通过 NAS 内网地址登录管理员并验证当前密码；开启 2FA 时还需验证码。受封浏览器在内网可以进入登录和账号恢复页，其他管理 API 仍正常鉴权。

浏览器标识来自可清除 Cookie，User-Agent 可以伪造，不是实体硬件指纹。可靠的主要防护对象为可信获取的来源 IP。

## 独立会话

每次登录都有随机独立会话 ID，服务器在 `sessions.json` 中保存授权、到期时间、首次/最近 IP、浏览器信息和最近活动时间。可以单独退出一个会话；被撤销的 Cookie 下一次访问受保护接口即被拒绝，其余会话继续有效。列表是仍有效的登录授权，不代表设备此刻一定在线。

升级到新会话格式时会轮换签名密钥并让旧 Cookie 失效，因此需重新登录一次。其后普通重启保留有效会话和已撤销结果。“退出其他设备”及改密码继续保留，但同时轮换签名密钥；配置导出剔除管理员认证、会话、TOTP、恢复码和执行器控制授权，新实例需重新设置管理员并重新授权探针。

普通备份仍含运行所需的 FRP/Lucky/Dashboard 等业务凭据，须作为私密备份保存；本次没有把全部配置导出改造成无敏感信息的公开文件。

## 真实 IP 的可信边界

面板自己的 FRP 隧道改用 PROXY protocol v2，进入容器内仅监听 loopback 的专用端口 15098；普通 LAN HTTP 仍使用原面板监听端口。

- VPS 原始端口直接连接：以 FRP 传递的 TCP 原始对端为 IP，忽略用户自带 XFF。
- VPS 本机 Lucky 反代连接：当可信 PROXY 头表明外层 TCP 对端为 loopback 时，读取 Lucky 覆盖或正确追加的最后一个 XFF / X-Real-IP。
- 普通 HTTP 客户端或旧隧道：不凭客户自带转发头认定可信来源；无法取得真实 IP 时显示未知来源，并保留基础全局限流。

通过 PROXY listener 接入的连接始终保留“经过隧道”标记，包括原始对端为 VPS 私网地址的情况；这些连接不能获得 NAS 内网解除权限。

要求 Lucky 在 VPS 本机运行并正确处理转发头。CDN、多层代理、Lucky 的 bridge 网络部署需额外核实可信来源，不能直接把整个 Docker 子网列入信任。15098 不对 NAS 或公网发布。机制依据 [FRP 官方 PROXY protocol 配置](https://gofrp.org/en/docs/reference/proxy/#proxytransport)。

## 自动端口开关

每条线路都需要一次“准备自动保护授权”及一次 VPS 执行器安装/升级。安装命令固定使用与面板一致的版本镜像，避免面板与执行器协议不一致。控制使用独立随机密钥，策略含 nonce、到期时间、版本和归属签名。遥测密钥本身不能授权防火墙控制；NAS 探针不接收 VPS 防火墙策略。协议只传递整数端口，不传 shell 命令或任意文件路径。

VPS 执行器在已有探针容器中运行，使用 host 网络和 NET_ADMIN。它只操作以安装/线路 ID 派生的 `frpdeck_web_*` 表。规则不隐式放行全部私网来源，只保留必要 loopback。

1.7.3 将“默认保留”与“禁止修改”分开：有域名反代的 TCP 网页服务默认限制直连；SSH、VPN 等 TCP 管理/非网页服务默认允许直连，也提供开关，由用户明确选择限制。旧版本保存的管理端口 `direct=false` 不会在升级时自动生效，需要重新操作开关。选择关闭管理端口后，对应的域名 SSH 直连同样受限。UDP 不在此 TCP 防火墙开关的范围内。

当前线路实际使用的 FRP 控制、HTTPS 入口、HTTP 跳转和探针上报端口始终保留；执行器在 VPS 本机也核对固定保护端口。手动管理端口限制使用单独的签名授权字段，不能通过缺失保护列表绕过默认保护。

上方是首次安装或修复执行器的命令，自动执行启用后不再展示下方手动防火墙脚本。未开启自动执行时，手动命令默认折叠，可以自行展开使用；它们不属于第二个必须完成的安装步骤。

管理端口开关需要同时升级面板和 VPS 执行器。先升级面板，再从页面重新生成安装参数；新参数仅固定当前线路的入口/控制/上报端口。旧执行器或仍固定 10022 等端口的旧安装参数不会接受管理端口限制，页面会显示待升级或执行失败，已有规则保留。网页端口的旧签名协议保持兼容。

开关保存后显示待下发，执行器约 10 秒内取到策略，下一轮上报回执，通常约 10–20 秒完成；只有实际执行、核对和持久化后返回签名回执才显示 VPS 规则已生效。核对范围包括归属、端口集合、input/forward hook、优先级、规则顺序及 drop 表达式；链被清空或改为放行时不会显示已生效。使用 [nftables 官方 JSON 输出](https://netfilter.org/projects/nftables/manpage.html) 检查内核当前规则。独立公网可达性验证仍是另一项结果：同一 VPS 代理的本机连接可以命中 loopback 保留，不能据此判断外部直连开放。

应用失败尝试恢复上一份规则；持久化失败也会回滚。成功策略保存到执行器 `/data/firewall-state.json`，探针或主机重启时先恢复最后的有效策略，NAS 不可达时也保留保护。断网显示离线，新设置不被假报为已生效。

## 从现有手动防火墙移交

1. 先保存 `nft list ruleset`、`nft list table inet frpdeck`、旧探针 `docker inspect`、原镜像 ID 和原数据目录。命令与 inspect 可能含密钥，文件应为 600。
2. 加载已校验的 1.7.3 镜像到 NAS 和两台 VPS，NAS 保持原 `/data` 卷后升级。从 1.7.2 升级保留有效会话；更早的旧会话格式需重新登录。
3. 在 NAS 页面逐条准备自动保护授权，复制该 VPS 的专用安装参数。现有探针先停止并改名保留，使用原匿名卷的实例不要直接删除卷。
4. VPS 停用旧 `frpdeck-firewall.service` 的自动重载，保留当前内核规则。执行器部署使用持久化目录 `/opt/frpdeck/firewall/<归属>`。
5. 页面生成的执行器命令默认不删除旧表。确认 `inet frpdeck` 为本次要替换的手动规则并完成备份后，首次安装命令才额外加入 `-e FRPDECK_FIREWALL_ADOPT_LEGACY=1`。只有新受管表已执行、核对并保存后，才移交旧表。未授予此权限时旧表不被删除，界面不会声称放行已成功。移交完成后移除该环境变量再重建执行器，避免以后误接管别的实例创建的同名表。
6. 检查域名、WebSocket、媒体播放、SSH、FRP 控制、所有同源代理端口；在另一公网出口验证 8096/19998/19999 等闭合，然后验证切换一个网页开关、回执和恢复。

NAS 上的端口映射、路由器转发和 IPv6 防火墙不属于本 VPS 执行器的自动修改范围。Emby 的用户密码、令牌和播放权限也独立于 FrpDeck 登录防护。

## 探针健康检查

探针不提供面板 HTTP 服务。新版本 `-health` 检测探针最近成功上报的心跳，180 秒无成功上报会判定不健康；面板模式继续检查面板 `/healthz`。这是修正原先探针继承面板 5000 健康检查的误报。

## 回退

先恢复已备份的手动防火墙，再停止当前执行器，恢复旧探针与 NAS 镜像；保留所有数据卷。新表有独立名字，回退只处理该安装的表。禁止 `down -v`、删除 `/data` 或清空 Emby 数据。回退到旧会话格式需重新登录，且会重新暴露此前已报告的旧会话/备份风险。

## 1.7.3 主题与兼容性

1.7.3 新增可选轻简主题，原三套配色、各页面、设置、图表、单线/并行及每服务线路选择保留。动效开关使用独立本地偏好键，不重置已有主题和隐私设置。本轮沿用上一版容器权限、Docker socket、数据目录和授权绑定方式；不宣称已完成非 root FPK。

从 1.7.2 升级继续保留当前会话和配置；从更早的旧会话格式升级，仍适用上文一次性重新登录说明。新增管理端口开关须先升级面板，再升级服务器探针并按新安装参数授权执行器；旧执行器不会收到无法解释的管理端口策略。不要覆盖旧版本镜像或已发布安装包。
