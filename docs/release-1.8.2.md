# FrpDeck 1.8.2

本版修复无 VPS、NAS 本地 Lucky 的业务流量采样和旧版反代兼容，完善配置恢复与升级保护。应用名称保持 **FrpDeck 内网穿透管家**。

## 修复内容

- 本地 Lucky 线路无需 VPS 字段即可采集域名业务流量，进入服务账本和趋势；NAS 公网流量仍由 NAS 探针独立统计，不同口径不相加。
- 旧版 Lucky 缺少域名计数时明确提示不可统计，避免把能力缺失显示成正常零流量。官方 2.5.1、2.7.2 的反代仍可使用；2.27.2 已验证真实域名传输与账本续记。
- 修正 Lucky 2.5.1 的反向代理类型：保存成功仍可能无法实际转发的问题。只修复 FrpDeck 明确归属的规则，独立规则保留。
- 修复来源切换、TCP/UDP 汇总、配置备份恢复、旧登录覆盖新密码和停止后意外重启等问题；错误计数、无效地址及重定向返回明确状态。
- 页面明确“今日业务流量”，区分采集中、未采集、来源错误和有效零流量；无服务器不显示线路计费用量。

## 公网 IPv4 / IPv6 + NAS 本地 Lucky

没有 VPS 也可使用 NAS 公网统计，前提是启用 NAS 公网探针且采集正常。仅连接 Lucky 管理接口不能获得整台 NAS 的公网总量。

本次使用官方 Lucky 2.27.2 与真实 nftables，在隔离 Linux 命名空间验证了 host/原生 IPv4、host/原生 IPv6、bridge IPv4 DNAT、bridge IPv6 路由的实际传输：入口归属正确，内部反代只计一次，LAN v4/v6 和管理 API 不进入公网总量。真实家庭路由器、NAS 生命周期和 TLS 证书链仍需结合部署环境验收。

域名业务量可能包含经相同入口的内网访问与 HTTP 开销；NAS 公网量、域名业务量、隧道量和服务器计费量不能相加。播放器 302 后直接访问第三方 CDN 的视频数据未经过 NAS，不计作 NAS 流量。

## 升级要点

- **从 1.8.1 升级：更新 FrpDeck 主程序即可，1.8.1 NAS/VPS 探针继续兼容。**
- **仍使用 1.8.0 NAS 探针：需要升级 NAS 探针。** 保留原密钥、回调、权限和挂载，拉取新镜像后重建原容器；只重启不会换镜像。旧 VPS 基本采集仍兼容。
- 保留完整主程序数据目录、线路、授权与历史。升级前停止主程序并备份完整数据目录。
- 已有密码可继续登录，首次成功验证后迁移 Argon2id。**迁移后回退旧版需要恢复升级前完整备份，不能只退镜像。** 备份之后的新记录不会自动进入旧版。
- 无需重新生成探针密钥、清空账本或删除 Lucky 子规则。过去未采集的数据不能补造。

## 验证与分发

全量测试、竞态检测、最低 Go 1.23.12、正式 Go 1.27.2 Alpine、16 组浏览器检查、3 个官方 Lucky 版本、两条官方 FRP 0.64.0 TCP/UDP 线路及 Docker 升级/回退验证通过。真实设备和复杂网络的边界如上，不承诺运营商计费级精度。

Docker 普通与 fnOS 分发提供 amd64、arm64、arm/v7。飞牛应用中心以实际审核上架版本为准，版本发布不代表应用商店已上架。官网与 GitHub 不提供独立 FPK、源码或 Compose 安装附件；官网截图保持原有香槟金深色，不随本次发版更换。
